# StreamCut — архитектура highlight-отбора: бриф для агента

Этот документ — единый источник правды по тому, что мы строим в highlight-пайплайне.
Цель: чтобы решения не переоткрывались, слои не путались, а измерения не выдавали
артефакты за сигнал. Читать целиком перед изменениями в детекции/отборе/слиянии.

---

## 0. Принцип в одну фразу

**Одна временная ось. N скореров. Одно арифметическое слияние. Человек режет.**

Каждый слой имеет РОВНО одну работу. Спутать работы слоёв = ходить по кругу
(крутить порог детекции, пытаясь починить precision, и наоборот).

---

## 1. Поток данных и слои

```
Стрим (аудио + лог чата)
  ├─ Whisper → транскрипт с таймкодами        [ТЕКСТ-ОСЬ, наследует слепоту Whisper]
  ├─ Silence-сегментация → тайм-ось/границы    [нейтрально]
  ├─ Аудио-DSP → громкость/смех/питч           [ОБХОДИТ Whisper]
  └─ Чат → плотность/всплеск                    [ОБХОДИТ Whisper]
       │
       ▼
  ДЕТЕКЦИЯ (LLM, Qwen)  — по транскрипту на тайм-оси
       │  «тут что-то есть?» → пул ~100 кандидатов, recall 90%
       ▼
  СЛИЯНИЕ (арифметика, без модели) над пулом:
       3 скорера → ранги → взвешенная сумма рангов → ранжированный пул
       │
       ▼
  РУЧНОЙ РЕЗ (человек)
```

### Ключевой факт про Whisper
Whisper стоит ПЕРЕД детекцией и задаёт потолок всего вербального слоя.
Транскрипт развалился (напр. «сэш сэлэл ай ай суда») → детекция и text-worthiness
слепнут, и ничто ниже по цепочке этого не вернёт. Поэтому невербальные хайлайты
(визуальный гача-дроп, юмор в подаче) текстовый слой берёт плохо ПО ПОСТРОЕНИЮ.
Чат и аудио черпают из сырых модальностей в обход Whisper → они ортогональны тексту
и ловят ровно то, что текст пропускает. Это не «ещё сигналы для надёжности» —
это закрытие конкретной слепоты Whisper.

## 2. Два слоя суждения о моменте — НЕ путать

| | ДЕТЕКЦИЯ | СУЖДЕНИЕ (слияние/скоринг) |
|---|---|---|
| Вопрос | «тут что-то есть?» | «это хороший клип?» |
| Вход | чанк, локально | кандидат + полный контекст |
| Цель | **recall** (не пропустить) | **precision** (поднять годное в топ) |
| Провал = | потерянный хайлайт (необратимо) | шум наверху списка (обратимо) |
| Сложность | низкая — Qwen тянет | высокая — узкое место |
| Объём вызовов | весь стрим (дёшево) | только по пулу (дорого, но мало) |
| Чинится | понижением порога | добавлением сигнала/контекста |

Детекция оптимизирует recall: лучше пропустить лишнее (отсеется), чем выронить
истинный (потерян навсегда). 90% recall = успех детекции, шум в пуле — норма.

## 3. Где LLM, а где нет

LLM ровно в ДВУХ местах:
1. **Детекция** — незаменима и доказана (90% recall). Не трогать.
2. **text-worthiness** — ОДИН из трёх голосов слияния (вербальная ось). Понижена
   из «судьи» до «избирателя».

LLM НИГДЕ не ранжирует и не отбирает финально. Это прямое следствие измерений:
- LLM-как-ранкер (select-to-N) = **0.50, рандом**.
- LLM-как-оценщик-одного (worthiness) = **0.604, слабо**.
Порядок выдачи решает арифметическое слияние, не модель. Надёжность берётся не из
силы LLM, а из того, что решение ВЫНЕСЕНО из LLM в ансамбль ортогональных сигналов —
слепое пятно каждого закрывают другие, ни один (включая LLM) не точка отказа.

Whisper и faster-whisper — нейросети, но НЕ LLM. Аудио-DSP и чат-плотность —
чистая арифметика/DSP, моделей нет.

Следствие: размер модели — НАИМЕНЬШИЙ рычаг. Более жирный Qwen поднимет один голос
из трёх; chat и audio не трогает. Рычаг — в модальностях, не в размере модели.

## 4. СЛИЯНИЕ — зафиксированное решение (НЕ переоткрывать)

```
score = w_text · rank_text  +  w_audio · rank_audio  +  w_chat · rank_chat
```

Правила, каждое с обоснованием:

- **Складываем РАНГИ или z-оценки, не сырые скоры.** У density и worthiness разные
  шкалы — иначе одна случайно задавит другую.
- **Аддитивно, НИКОГДА не мультипликативно.** Сложение = голосование (сильный в одном,
  молчащий в другом → всё равно поднимается). Умножение = вето (любой множитель ≈0
  обнуляет продукт). Вето теряет «сильное-в-одном»: дедпан-хот-тейк = текст высокий,
  аудио плоское, чат молчит → `text×audio×chat` ≈ 0 → лучший контент убит. Запрещено.
- **«Важнее» = больший ВЕС, не умножение.** `w_text = w_audio = 1.0 > w_chat`.
  Умножение выражает «обязателен», а не «важнее» — это другое и опасное.
- **w_chat авто-масштабируется по объёму чата:**
  `w_chat = min(1.0, total_chat_msgs / N_ref)`.
  Мало чата (маленькая аудитория) → чат тихнет, доминирует текст. Живой чат → голос
  растёт. Один пайплайн адаптируется к размеру аудитории без ручной перенастройки.
- **Тандем достигается ПОРЯДКОМ, не множителем.** Сложение само ставит «силён в обоих»
  выше «силён в одном» выше «слаб в обоих». Нелинейный бонус за совпадение не нужен и
  противоречит сохранению одиночек.
- **Опционально позже:** маленький `+ε` за согласие (оба ранга в топ-квартиле) как
  тай-брейкер между близкими — НЕ доминирующий член. Только когда есть ≥2 размеченных
  стрима, чтобы подобрать ε не на глаз.

### Recall священен
- **rank-all, не cut-to-N.** Отбор-в-N конвертирует ошибку ранга в безвозвратную
  потерю recall — это доказанный провальный режим (select-to-N упал до рандома).
  Показываем весь пул, переупорядочиваем, человек режет.
- **NMS w=45** — только дедуп для показа (100→~68 lossless при tol20). НЕ фильтр
  precision. w=60 уже теряет истинный, w=90 рушит recall. Окно привязано к tolerance.
- confidence детектора как ключ сортировки — ДОКАЗАННО случаен относительно годности
  (top-30 по confidence терял 9→5). Менять ключ на слияние.

## 5. Эпистемический статус — что доказано, что выбрано, что гипотеза

НЕ путать «теоретически связно» с «измерено». Паттерн проекта: цифра выглядит
сигналом, оказывается артефактом измерения. Уже случалось 4 раза (single-call 20% =
случайное совпадение; 0.604 сквозь 3-корзинный квантователь; эталон с мнимой утечкой;
0.804 на разных негативных классах).

**ДОКАЗАНО (на fixture 21, n=1):**
- Детекция recall 90%.
- chat-density разделяет метки vs случайные точки (ловит гача-климакс — невербальный).
- Ортогональность text/chat слепых зон — на механизме (кейсы @6630 трёп vs @11694
  климакс), не только на цифре. Это переносится на другие стримы.

**ВЫБРАНО, но НЕ валидировано:**
- Форма слияния (раздел 4) — выведена из требований, на данных не проверена ни разу.

**ГИПОТЕЗА (не измерено вообще):**
- Аудио-сигнал. Стоит в архитектуре на вере. Меряется тем же AUC-зондом, что чат.

**n=1 предупреждение:** G=10 меток → любая precision-метрика = ступенька в 1 клип,
любой шум опрокидывает. Ничего нельзя хоронить или короновать на одном стриме.
Нужно 2-3 размеченных стрима.

## 6. ОТКРЫТЫЙ ВОПРОС — слой суждения

Это главное нерешённое. Не строить слой суждения, пока не закрыт пункт (1).

**Проблема фундамента:** `ground_truth/21.json` (коммит 2bb70fe5) — это 10 СЛЕПЫХ
пиков Claude Opus 4.8, которые человек потом отсмотрел и одобрил. Это УЗНАВАНИЕ
(ратификация правдоподобного списка), НЕ независимая человеческая разметка. Человек
видел то, что модель подняла — но не видел того, что она пропустила (ложные негативы
невидимы при ревью).

**Следствие:** весь бенчмарк (90% / 0.604 / 0.50) считался МОДЕЛЬ-ПРОТИВ-СЕБЯ.
Неподвижной человеческой точки отсчёта не было. Это вероятная причина «хождения по
кругу»: измерения плыли вокруг эталона, который сам был выходом измеряемого.

**Что нужно, по порядку:**

1. **Независимый human ground truth.** Алексей размечает 10 клипов ВСЛЕПУЮ, не глядя
   в 21.json (или на свежем VOD, если 21 уже в памяти). Сверить с пиками Opus.
   - Совпали → слепое суждение сильной модели ≈ вкус человека → бенчмарк валиден,
     слой суждения оправдан.
   - Разошлись → пики модели ≠ человеческий клип → весь бенч пересчитывать против
     человека.
   - Частично → карта, на каком КЛАССЕ моментов LLM совпадает (вербальное?), на каком
     нет (невербальное?) → где доверять LLM-сигналу, где обязательны чат/аудио.

2. **Только потом — тест воронки «дёшево → дорого».** Узкое место не качество
   суждения сильной модели (Opus достал хайлайты вслепую — суждение в контенте
   ИЗВЛЕКАЕМО), а ОБЪЁМ дорогих вызовов. Поэтому:
   дешёвый recall-слой (детекция + чат + аудио) жмёт 3.5ч → ~20-30 кандидатов без
   потери годного → бинарное суждение «работает как самостоятельный шорт, есть хук в
   первой секунде?» ТОЛЬКО по этим 20, с ПОЛНЫМ ±60с контекстом (не список, не 220
   симв — именно формат убивал select-to-N и worthiness, а не суждение).
   - Сначала Qwen-full-context бинарно (дёшево, без новой инфры).
   - Слаб → Groq-hosted модель покрупнее (было в дизайне для VPS, дёшево на 20
     вызовах).
   - Opus-API — крайний случай.

   Бинарный clip-worthiness с полным контекстом бьёт прямо в узкое место воронки —
   провал swipe-through в первую секунду.

## 8. Чего НЕ делать

- Не возвращать LLM на ранжирование/отбор-в-N.
- Не перемножать сигналы в слиянии.
- Не резать пул до фиксированного N (ломает recall).
- Не сортировать по confidence (доказанно случаен).
- Не понижать порог детекции, пытаясь починить precision (разные слои).
- Не делать выводов о precision на одном стриме (n=1 = ступенька в 1 клип).
- Не строить слой суждения до независимого human ground truth (раздел 6.1).
- Не принимать «теоретически связно» за «измерено» (раздел 5).
